Исходный код класса OrderService нарушает несколько принципов SOLID:

- Single Responsibility: Метод processOrder делает всё сразу: валидирует, считает (и сам выбирает как считать) скидку/комиссию/финальную стоимость, печатает чек и сохраняет заказ.
- Open Closed : Добавление нового типа клиента или оплаты требует изменения существующего метода (добавление else if).

---

После рефакторинга внесены следующие изменения:

- Класс Order реализует паттерн Builder для более удобного создания объектов
- Логика валидации вынесена в отдельные классы, которые реализуют интерфейс Validator\<Order>. При использовании Spring контекст будет сам собирать список валидаторов и запускать проверку на каждом из них. Т.о. поддерживается OCP и реализован паттерн Observer
- Реализован паттерн Strategy, алгоритмы расчёта скидки и комиссии вынесены в отдельные классы, что позволяет менять их независимо друг от друга и легко покрывать юнит-тестами
- Реализован паттерн Factory, фабрики инкапсулируют логику создания объектов. Клиент (OrderService) не знает, какой именно класс стратегии он получает, он работает только с интерфейсом
- Добавлены новый тип клиента и способа оплаты для демонстрации изменений
